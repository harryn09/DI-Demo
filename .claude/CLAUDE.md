# CLAUDE.md

A public-facing website for the **Digital Identity Team, Ministry of Education (New Zealand)**, introducing the Ministry's four Digital Identity Services (ESL, Learner Identity Broker, NSI, Enrol) to the education sector.

Static HTML/CSS/JS pages (homepage `index.html`, one page per service, shared assets in `assets/`) served from `wwwroot/` by a thin ASP.NET Core host (`Program.cs`), which also provides EntraID sign-in/out and an Azure Table Storage-backed user profile (see `tech-stack.md`). Test locally with `dotnet run` from the repo root (needed for auth); `dotnet-serve --directory c:\Projects\DemoSite\wwwroot --port 8080` still works for quick static-only checks.

## Contact

All outbound communication generated by this project — form submissions, support/contact links, notification recipients — goes to **harry.nguyen@education.govt.nz**. This is the configured value in `wwwroot/assets/js/config.js` (`forms.esl120.recipientEmail`); when adding new forms or contact points, wire them to that same config value rather than hard-coding a different address, and keep any fallback defaults (e.g. in `wwwroot/assets/js/forms.js`) consistent with it.

## Commands

- `dotnet build DigitalIdentitySite.csproj` — build.
- `dotnet run` — run locally (serves `wwwroot/` + auth endpoints; needs EntraID app registration and storage connection string via `dotnet user-secrets`, see `tech-stack.md`).
- `dotnet publish DigitalIdentitySite.csproj --configuration Release --output ./publish` — what CI runs before deploying (see `release-process.md`).
- No test suite exists in this repo currently.

## Architecture

The C# layer is intentionally thin — it exists to add auth/profile on top of otherwise-static marketing pages, not to run business logic:

- `Program.cs` — app startup, OpenID Connect config, and the `OnTokenValidated` hook that upserts the signed-in user's profile on every login.
- `Endpoints/AccountEndpoints.cs` — minimal API routes (`/account/signin`, `/account/signout`, `/api/me`).
- `Pages/Account.cshtml(.cs)` — the single authenticated Razor Page (`[Authorize]`) shown after sign-in.
- `Models/UserProfileEntity.cs` + `Services/UserProfileStore.cs` — the Azure Table Storage-backed user profile record and its sole access point.
- Everything else the visitor sees (`wwwroot/*.html`, `wwwroot/assets/`) is static and served unauthenticated via `UseStaticFiles`/`UseDefaultFiles` — no server-side rendering or templating.
